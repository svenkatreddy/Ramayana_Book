# Translations

Verse-aligned translations of the Ramayana, keyed to the Sanskrit chapters
under `san/`. Generated by `scripts/build-translations.py` — do not edit the
`en/` files by hand; re-run the script.

## Layout

```
translations/
  README.md
  en/<kanda>/chapter<N>.json     # English (Valmiki Ramayan Dataset, MIT)
  te/<kanda>/chapter<N>.json     # Telugu (Telugu Wikisource, CC BY-SA)
  hi/<kanda>/chapter<N>.json     # Hindi (future)
```

Each chapter file:

```json
{
  "kanda": "kishkindha_kanda",
  "chapter": 11,
  "language": "en",
  "source": "…",
  "verses": { "1": "English text of verse 1…", "2": "…" }
}
```

`verses` is keyed by our verse number as a string and is sparse: verses with
no translation are simply absent (the site then shows Sanskrit only — we
never invent translations).

## English source (credible, verse-aligned, MIT)

- **Dataset:** "Valmiki Ramayan Dataset" by Ashutosh Vijay — MIT licence.
  https://github.com/Ashutosh-Vijay/Valmiki_Ramayan_Dataset
- **Translation:** the dataset’s English prose translations draw on its
  documented sources — **M.N. Dutt’s English translation (1891–1894)**,
  **IIT Kanpur’s Valmiki Ramayanam** (https://www.valmiki.iitk.ac.in/),
  and **Gyaandweep** (per the dataset README’s Sources & Credits).
  Our Sanskrit follows IITK’s critical-edition numbering, so verse
  numbers line up one-to-one.
- **Gap-fill:** a handful of verses missing from the canonical file are
  filled from the cleaned copy of the same MIT dataset published in
  https://github.com/andvraman/valmiki-ramayana (documented there as the
  same dataset, manually corrected). Canonical entries always win.

Coverage: ~98.8% of our 23,334 verses. The remainder are mostly colophons
that were absorbed as "verses" and sarga bleed-through in a few legacy
chapters — not real verses, so no translation exists for them.

## Telugu source (credible, verse-aligned, CC BY-SA)

- **Source:** Telugu Wikisource, "వాల్మీకి రామాయణము" (CC BY-SA) —
  https://te.wikisource.org/wiki/వాల్మీకి_రామాయణము
- **Method:** `scripts/build-telugu.py` fetches each sarga page via the
  MediaWiki API and aligns our verse N with the page's Telugu prose for
  that verse. Pages use two contributor formats (explicit `[k-s-v]`
  brackets, or prose positionally following its shloka(s)); the parser
  handles both, plus Telugu-script digits in verse markers.
- **Coverage (honest):** only ~322 verses across 10 Bala Kanda sargas.
  Most Wikisource sarga pages are Sanskrit-only — the volunteer Telugu
  translation there is still in progress. Verses without Telugu are left
  untranslated, never invented. Re-running the script picks up new
  translations as contributors add them.

## Adding a language

No hard cap — `LANGS` accepts any number of languages; the reader
toolbar, verse blocks and show/hide logic are generated per entry.
Keeping it to a handful keeps the reader bar readable.

1. Create `translations/<code>/` with the same per-chapter JSON shape
   (`language` = the code, e.g. `"te"`).
2. Add the language to `LANGS` in `site/scripts/sync-content.mjs`:

   ```js
   const LANGS = [
     { code: 'en', label: 'English', native: 'English' },
     { code: 'te', label: 'Telugu', native: 'తెలుగు' },
   ];
   ```

3. Add a font + a `.verse-tr[data-lang="<code>"]` rule in
   `site/src/styles/custom.css` if the script needs one.
4. Re-run the site sync/build. The reader toolbar, verse blocks and
   show/hide logic pick the new language up automatically — no other
   code changes needed.
